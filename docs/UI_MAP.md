## 周五「额外周末」（野上泷天赋）

- 出现条件：`第N周 星期五` 的训练日主界面，右侧多出一个「出行」按钮。
  这是天赋触发的**额外周末**，当天仍可训练/休息，也可以直接出行去户外地图。
- 实测：2026-10-30 16:05，第 1 周 星期五，体力 82/130，零用钱 169。

界面要素（1549x871）：

| 位置 | 内容 | 备注 |
|---|---|---|
| 顶栏左 | `第1周` `星期五` | 日期解析同平时 |
| 顶栏中 | `82/130`、`169` | 体力 / 零用钱 |
| 左上 | `3天 赢得比赛` | 比赛倒计时 |
| 右上 | `商店`（图标+文字） | y≈0.21h，和比赛日的商店入口同一位置 |
| 右侧竖排 | `出行`(y≈0.55h)、`休息`(y≈0.72h) | x≈0.85~0.95w |
| 右下 | `训练`（黄色大按钮） | y≈0.83h |
| 底部 | 六维属性面板 | 投射/弹跳/运控/体能/防守/意识 |
| 中间 | 队长立绘 + 台词 | 台词会出现「今天可以出行哦！要不…」 |

操作：点**右侧整词**「出行」→ 进入户外地图（和周六/周日同一张地图）。

坑：

1. 台词里有「今天可以出行哦！要不…」，`click_text("出行")` 会命中这句台词
   （日志 `left_click 今天可以出行哦！要不 (950, 182)`），点了没有反应。
   必须限定 `x > 0.75w` 的整词「出行」。
2. 一天只能出行一次，否则「出行 → 地图 → 退回首页」打转；
   `weekend_state()["outing_done"]` 记录，非周末再遇到就直接返回主界面。

代码：`handlers/weekend.py: handle_go_out`、`parsers.py: weekend_state`。

扭蛋流的周末口径（因为这个天赋，周五也算周末）：

- 周五 / 周六 / 周日：只进「步行街（扭蛋）」或「餐厅」。
- **钱 > 300 → 先进步行街消费**（钱多就该花掉，别留到最后剩一堆）。
- 钱 ≤ 300 时看队友：**两边都有队友 → 步行街**；只有一边有队友 → 去那一边；
  **都没队友**：周五 / 周六 → 餐厅赚钱；周日 → 步行街消费。
- 地图上步行街上方出现彩色爆炸标签 **「扭蛋增强！」** 时：不管钱和队友，
  直接进步行街（最高优先级）。
- 去了步行街但**没消费**（没钱 / 没买到）→ 再去餐厅打工；买到东西就不去了。
- 餐厅打工：**队友多**的优先；一样多选右边（耗精力那张）；**右边精力不够就选左边**。
- 代码：`constants.WEEKEND_PLAN`、`flow.weekend_priority`、
  `handlers/weekend.py: prefer_mate_venue / restaurant_order`。

## 周末地图的标记

| 标记 | 外观 | 含义 |
|---|---|---|
| 队友气泡 | 深藏青圆角块 + 1~2 个圆头像 | 该地点有队友（`venue_has_mate`） |
| 打折！ | 橙色爆炸标签，贴在地点左上方 | 该地点在打折（`venue_on_discount`） |
| **扭蛋增强！** | **彩色（蓝/紫/青渐变）爆炸标签**，贴在步行街左上方 | 步行街扭蛋加成，优先去（`prefer_mate_venue`） |
| 绿色定位针 | 绿色水滴图标 | 当前所在位置，不是可点入口 |

实测：2026-10-30 第 5 周星期五（野上泷额外周末），步行街有「扭蛋增强！」，
同时餐厅/公园各有一个队友气泡。

**「扭蛋增强！」必须连位置一起判**（2026-11-01 修，`venue_has_street_boost`）：
原来只 `match_text(texts, ("扭蛋增强","扭蛋加强"))`，全屏出现这四个字就生效，
不管它贴在哪 → 别处（队友台词等）出现同样字眼就会误判成「步行街有加成」，
于是**不管钱和队友**直进步行街。

现在要求标签贴在**步行街名字的左上方**（Δcx ≤ 0.20、Δcy ≤ 0.12、且在左边）。
实测 10 张真实地图帧几何一致：标签 cx=0.457 cy=0.809、步行街 cx=0.564 cy=0.858
（Δcx=0.105~0.107、Δcy=0.048~0.049）。离线复现见 `docs/UI_MAP.md` 里那 10 个
`logs/events/1031-173714`、`1031-194957`、`1101-150917` 等事件帧。

## 扭蛋购买界面（含「增强款」）

- 实测：2026-10-30 第 5 周星期五，体力 130/130，零用钱 375。
- 要素：
  - 标题 `请选择1个扭蛋`
  - 三张卡横排，卡头是一条品质色带（**金 / 紫 / 蓝**）
  - 每张卡**右上角**可能有黄色斜标签 `增强款`（艺术字，OCR 会读成「增强款」）
  - 每张卡**左上角**可能有队友标记（`!` + 头像；这一版是**深蓝底浅色头像**，
    不是旧版的橙色气泡，位置也更靠下 ≈0.29~0.34h）
  - 卡底部价格药丸被红字「打折」压着：`100 → 90`、`60 → 50`
  - 卡内说明里也会出现「增强 额外获得体能+14」，那不是标签
- 选择优先级（用户 2026-10-30）：**品质（金/紫）> 增强款 > 队友**。
  - 蓝卡默认不买（除非体力低时要买「清空精力」卡换属性）。
  - 同品质里先看右上角「增强款」，再看左上角队友标记。
- 代码：`parsers.py: read_gacha_cards / has_mate_badge`、`handlers/weekend.py: handle_street`。

## 顶栏右上角图标条（倍速 / 历史记录 / 菜单 / 返回）

游戏顶栏最右边是**四个图标**，从左到右依次是：

| # | 图标 | 是什么 | 行为 | 中心坐标（相对） |
|---|---|---|---|---|
| 1 | `▶`+`2x` 字样 | **倍速** | 点击在 `OFF加速 → ▶1x → ▶▶2x → ▶▶▶3x` 之间**循环**；高倍率随游戏进程解锁（大师赛解锁 2x），**目前最高 3x** | (0.760, 0.044) |
| 2 | 文档/纸页 | **历史记录** | 显示刚刚发生了什么事件、获得了什么（例如「零用钱 +N」「某属性 +N」） | (0.819, 0.045) |
| 3 | 三横线 ☰ | **菜单** | 进入后有 `保存后中断` / `放弃` / `能力详情` / `队伍信息` / `设置` | (0.875, 0.052) |
| 4 | 圆角方块 + 箭头 | **返回** | 返回上一级 | (0.939, 0.043) |

坐标来源：`docs/shots/2026-10-26-subject-crit.png`（1920x1080）按「蓝灰色块」分割量出的中心点，四个图标 x 依次
0.748~0.772 / 0.805~0.834 / 0.861~0.890 / 0.918~0.960，y 0.013~0.075。同一帧序列三种分辨率归一化后一致。

### 倍速档位的判据（2026-11-01 现场逐档点过一遍）

- 点一次前进一档，顺序是 **`1x → 2x → 3x → OFF → 1x`**（OFF 在 3x 后面）。
- **图标里画几个三角 = 这个存档解锁到几档**：只解锁到 2x 时画两个三角（`docs/shots/2026-10-26-*`），
  解锁 3x 后画三个。**实心（蓝）的三角个数 = 当前档位**，其余是白色空心三角。
- 因此「**还有空心三角 → 没到顶；一个空心都没有 → 已到该存档最高档**」。
  这条判据**不需要知道上限是 2 / 3 / 4**，游戏以后再加档位也不用改策略代码。
  OFF 态是灰字「OFF / 加速」、没有三角，像素上和「全实心」几乎一样（solid 0.52 / hollow 0.01 vs 3x 的 0.51 / 0.00），
  **只能靠 OCR 判**。
- 逐档实测（三角行内像素占比）：
  | 档位 | 实心占比 | 空心占比 | at_max |
  |---|---|---|---|
  | 1x | 0.26 | 0.25 | False |
  | 2x | 0.42 | 0.12 | False |
  | 3x | 0.51 | 0.00 | **True** |
  | OFF | 0.52 | 0.01 | 像素不可信 → 走 OCR |
- 由此废掉了老的「右三角 ROI 蓝占比 > 0.45 = 2x」：那个 ROI 只覆盖第 2 个三角附近，
  1x/2x 都判成「未加速」，语义悄悄变成「已经到 3x」，函数却还叫 2x —— 名字、注释、日志三层同时说谎。
- 点击是**循环且一次一档**，所以策略必须**一拍只点一次**（本帧 `self.frame` 到下一拍才更新，盲连点会点过头，
  从 3x 连点两下直接回到 1x）。看门狗：连续 2 次点击状态毫无变化就锁到下周。
- 点击要点：**每一下都要重新 `ensure_foreground` + 先 hover 再点**。实测只抢一次前台连点 4 下，
  四帧全是同一个状态（点击被吃掉）。
- 工具：`tools/probe_topbar.py --cycle 4`（点 N 下、每下存图标条放大图 + OCR 档位小字）；
  离线回归 `tests/test_speed_readout.py`（四档整帧 + 旧 2x-only 存档，共 5 例，全过）。

### 另外三个图标的用法/禁区

- **历史记录**：只读、安全，**是「事件流水」而不是日志文件**（2026-11-01 现场翻完一遍）：
  - 面板顶部标题 `历史记录`，右上角 `X` 关闭，底部两个按钮（`放弃`/`确定`）是**底层的**，不属于面板。
  - 内容是卡片流：白卡 = 明细行（`获得了145零用钱`、`投射+10`、`高级智能篮球的熟练度增加了13`）；
    蓝色标题条 = 事件（`当服务员`、`训练`、`球队经理的加强训练`、`育才/花咲…`）；
    红色标题条 + 头像 = 剧情选项（`重要的是大家都在一起` → `投射+10` / `运控+10`）。
  - 顺序 **新的在下面**，往上翻看更早的记录。
  - 翻页方式：**滚轮几乎翻不动**（120×10 才挪一行）；**按住往上/往下拖 ≈ 一张卡**。
    到顶/到底用「列表区像素差 < 2」判定。
  - 覆盖范围实测：从 `笔记学习日`（今天这局第一次训练）到 `当服务员 → 获得了145零用钱`，
    一共 ~20 张卡，正好等于**当天那一局**（第1周 星期五 → 第3周 星期日，约 40 分钟）；
    再往前（10-31 及更早的存档）**没有**。
  - 用途：它把脚本读不准的数字写死了（零用钱 145、熟练度+13、`防守上限+257`），
    可以做**账目对账**的权威来源。工具：`tools/probe_history.py`。
- **菜单**：**不要点**。里面有 `放弃`（可能直接结束养成）和 `保存后中断`，误触等于毁局。
  唯一例外是显式需要「放弃」的收尾逻辑，必须单写 handler + 二次确认。
- **返回**：不要靠认图标，靠 OCR 文字（`EXIT_TEXTS`：`×/✕/X/《/く/</〈/‹/关闭/返回…`）或
  `BACK_POINTS` 两个死坐标；退出键不总在右上角（选队长/选择队友页在**左上角**）。

### 已知噪声：OCR 会把这一串图标硬读成汉字

整帧 OCR 经常把 2~3 号图标读成 `战昆三 / 艮三 / 数目三 / 战早三 / 战見三 / 成見三 …`（置信度只有 0.50~0.75，
正常文字都在 0.95+），全仓库日志里累计上万次。它们全落在 `x≈0.74~0.90w, y≈0~0.09h` 这一带，
`top_bar=(0,0,0.60,0.09)` 按框中心过滤时大部分被挡在区外；进区的（`早三`@0.55w、单字`三`@0.55w）
也只进周次/体力正则，匹配不上，无害。

**2026-11-01 已实现过滤**（用户两次指出「那不是字，是历史记录和菜单两个图标」）：
`ui/Defs.py: ICON_NOISE_RE / ICON_NOISE_BAND / ICON_NOISE_CONF` +
`BaseGirlsTask.drop_icon_noise`，挂在 **`_ocr_region` 这个唯一 OCR 出口**上，
所以 handler / `_tick_texts` / 存证 dumps 里的 `ocr.txt` 都不再出现这些假汉字。
判据是「整串匹配 + （落在图标带里 或 置信度 < 0.90）」，真文本不受影响。

注意：ok-script **框架自己**每拍还会 `DEBUG` 打一行原始 OCR 结果（`task:ocr_zone … found result: [...]`），
那行里的 `早三/昆三` 属于框架日志，只能靠**不用 debug 启动**（`main.py` 而不是 `main_debug.py`，
`config['debug']=False` → 日志级别 INFO）才消失。
