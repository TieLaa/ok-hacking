# 提示词手册（新项目开场 / 中途纠偏）

> 用途：下一个游戏自动化项目启动时，直接复制这里的模板，避免重复踩本项目的坑。
> 每次踩到新坑，先问「当时哪句话没写，才会让 agent 走错」——补到对应小节，不要只补代码。

## 0. 一句话原则

**在提示词里写清「边界」和「验收」，比写清「要做什么」更重要。**
agent 不缺执行力，缺的是「什么不许做」「怎么算做完」。

## 1. 新项目开场模板

```text
目标：给 <游戏> 做 <范围> 自动化，框架用 ok-script（版本锁 requirements.txt）。

先做环境确认，不要写业务代码：
1. 读 <模板仓库> 的 config.py / BaseTask 用法，列出接入点；
2. 确认游戏进程名、窗口类、客户区分辨率、是否管理员权限；
3. 用 tools/ 下的抓图脚本验证能稳定出帧（窗口部分可见即可，不要最小化）；
4. 把上述事实写进 docs/ENVIRONMENT.md，再开始写任务。

硬约束：
- 路径纯英文，Python 3.12 venv；
- 没有实测过的结论，标注「待验证」，不要写成事实；
- 每完成一个可验证成果就 commit 一次，不要攒着。
```

**为什么**：本项目开局就卡在「游戏是管理员进程」和「窗口被遮挡 WGC 无帧」，这两条都是环境事实，不是代码问题。先落 `docs/ENVIRONMENT.md`，后面每个会话都能查。

## 2. 加界面前（最常用）

```text
加一个界面：<界面名>。
证据：截图在 <路径>，OCR 文字在 <同目录 ocr.txt>（先读文字，不要直接读图）。
要求：
1. 先跑 tools/check_handlers.py <图> --cache --verbose，确认现有 handler 没认走；
2. 判据只用这个界面独有的文案/区域，写进 docstring 说明为什么不用别的词；
3. handler 放进 <域>.py，并在 handlers/__init__.py 里说明为什么放这个位置；
4. 更新 expected.json，全量回归必须 exit 0；
5. 一个界面一个 commit。
```

**为什么**：不写「放哪个位置」和「为什么」，agent 会把新 handler 追加到末尾，被前面的宽松判据吃掉，表现是「改了但没生效」。

## 3. 改判据 / 修 bug 前

```text
先复现，再改。
1. 从 logs/debug/<时间>_<tag>/ 读 ocr.txt + actions.txt，指出卡在哪一步、哪个 handler 命中；
2. 如果是 OCR 漏判，再读 frame.jpg（最多 1 张）；
3. 改完跑 tools/check_handlers.py --cache，贴出 exit code 和差异行；
4. 回归没通过不许说「修好了」。
```

**为什么**：本项目最常见的返工是「凭印象改判据，结果别的界面被抢」。回归断言是唯一能兜住的东西。

## 4. 读图约束

```text
这个会话最多读 3 张图。优先读 ocr.txt / actions.txt。
必须读图时：只读与当前问题相关的那一张，读完在回复里写一句「从图里看到了什么」，
不要连续贴多张 1080p 截图。
```

**为什么**：1080p 图每张约 1 MB（JPEG），历史图每轮重发，实测 19 张图把每轮从 5 秒拖到 90 秒。

## 5. 重构前

```text
先 commit，再重构。
1. 保存重构前的回归基线（check_handlers.py --cache > baseline.txt）；
2. 只搬代码不改行为；
3. 重构后逐张对比命中结果，有差异必须解释；
4. 重构和功能改动分成两个 commit。
```

**为什么**：本项目 2117 行单文件拆分时，漏搬了类级常量 `W_MATE`，回归立刻抓到 `subject-crit` 未命中。没有基线就只能靠猜。

## 6. 改完怎么验证（MCP 循环）

```text
改完任务后不要重启 GUI，按这个顺序验证：
1. tools/check_handlers.py --cache，exit 0（识别层，秒级）；
2. list_tasks 拿到 task_id 和源码路径，确认你改的是同一份文件；
3. reload_tasks(task_ids=[...])，轮询 get_run_status 到 succeeded；
4. run_task 提交 tools/mcp/probe.py（先确认大厅/OCR/顶栏），再提交对应 smoke；
5. 失败先读 logs/mcp/<run_id>/ 的 status.json + run.log + 产物图，再改代码。
注意：改了 src/tasks/training/ 下被 import 的模块（parsers/handlers/flow）必须重启
runtime，reload_tasks 只刷新已注册任务模块。
```

**为什么**：不写这条，agent 会「改完直接说好了」；或者把 TrainingTask 整段复制进临时脚本验证，验证的是一份克隆而不是真实实现。

## 7. 配置类问题
```text
改行为前先确认三处：
1. 代码里的 default_config / config.get 默认值；
2. configs/<Task>.json 里用户已有的覆盖值；
3. configs/devices.json 是否覆盖了交互方式。
```

**为什么**：「改代码默认值对已存在的 json 无效」这个坑，本项目在「周末允许进步行街」上踩过一次，表现为「代码明明改了，运行时还是去公园」。

## 8. 交接模板（换会话 / 换 agent 时用）

```text
交接：<任务名>
目标：
现状（已验证 / 未验证分开写）：
下一步（按顺序，可执行命令）：
涉及文件：
现场状态（游戏停在哪、配置关键项）：
不要做什么：
```

**为什么**：交接里写「不要做什么」比写「要做什么」更能防止下一个 agent 乱动。

## 9. 反面示例（这些话会直接导致返工）

| 不要这样说 | 改成 |
|---|---|
| 「把 XX 修一下」 | 「XX 的现象是 A，预期是 B，先复现再改」 |
| 「顺手优化一下」 | 「只改 XX，其他保持不动」 |
| 「加个 handler」 | 「加 handler，说明判据和插入位置，并更新 expected.json」 |
| 「应该没问题吧」 | 「跑回归，贴 exit code」 |
| 「读一下这些截图」 | 「先读 ocr.txt，需要时最多读 1 张图」 |
| 「重构一下代码」 | 「先 commit，存基线，只搬不改，回归对比后再说」 |

## 10. 每次新坑补一条

格式：

```text
### <坑的名称>
- 现象：
- 根因：
- 提示词里应该加的那句：
```

### 重构后文件相对路径偏移

- 现象：日志说「存证 logs/unknown/xxx.jpg」，但 `logs/` 里没有文件。
- 根因：用 `dirname(__file__)` 数层数找项目根；文件从 `src/tasks/` 移到 `src/tasks/training/` 后少算一层，写到了 `src/logs/`。
- 提示词里应该加的那句：**「重构搬文件后，所有基于 `__file__` 的相对路径都改成统一的 `PROJECT_ROOT` 常量。」**

### 兜底点击不参与卡死检测

- 现象：不认识的界面一直点屏幕中央，既不 debug 也不停，最后耗光操作数。
- 根因：卡死检测只在 handler 命中时记录「点击后指纹」，兜底分支没记，`_no_change` 永远是 0。
- 提示词里应该加的那句：**「兜底路径也必须记录点击后指纹，和 handler 路径共用同一套『3 次无变化』判定。」**

### 放宽判据会抢已有界面

- 现象：为让事件三选一识别《书名号》选项，放宽了长度和字符限制，结果剧情三选一被同一 handler 抢走。
- 根因：两个界面 UI 完全一样（三个白底横条 + 右上跳过），只能靠文字特征区分。
- 提示词里应该加的那句：**「放宽 handler 判据后必须跑全量回归；如果两个界面 UI 相同，先确认它们的行为是否应该一致，再决定是改判据还是改期望表。」**

### 二级确认页

- 现象：点完「划船」后停在详情页，每拍点中央都没反应。
- 根因：地点详情是二级确认（「前往划船」），旧流程只处理了第一级。
- 提示词里应该加的那句：**「加地点/活动 handler 时，先确认是一级还是两级确认（选择 → 前往XXX）。」**

### 一键启动脚本误点别的任务卡

- 现象：`tools/start_ok_task.py` 报「已排队」，跑的却是 `Configuration Demo Task`；OK 窗口里任务卡有 4 张，日志都打 `queued onetime_task`。
- 根因：脚本只判断「有没有排上队」，不核对任务名；OK 刚启动头几秒点击还会被吞，候选 y 逐个试时越试越往下，最后停在示例卡。
- 提示词里应该加的那句：**「点任务卡必须核对日志里的任务名（`训练循环`/`TrainingTask`），排错了要报错退出，不能当作成功。」**

### F8 轮询误报把任务停掉

- 现象：无操作时任务突然报「按下 F8（轮询兜底）→ 请求停止」。2026-10-27 首尾两局各一次。
- 根因：`GetAsyncKeyState` 单拍采样就判定按下，手柄/输入法/其他软件转发的瞬时状态也会命中。
- 提示词里应该加的那句：**「轮询按键必须连续 N 拍确认（本项目 3 拍 ≈150ms），单拍只记 debug。」**

### 信息栏被当成「竖向三选一」

- 现象：QuickMatch 挂在全国大赛关卡列表，每 0.5 秒点一次「对手实力」，点了 30 秒没反应，最后因为切窗口才被前台检查拦下。
- 根因：`choice_candidates` 只按「屏幕中部 + 同列竖排 + 短文本」判形态，关卡详情页右侧的「对手实力／关卡加成／奖励预览」、周结算页左列的「控卫／分卫／小前／大前／中锋」、周末前对话字幕「我要去和小式一起去看电影」都完全符合；TriggerTask 又没有看门狗。
- 提示词里应该加的那句：**「竖向选项是**居中一列**（实测 cx≈0.50）：候选先收窄到 0.38~0.62 再判形态，贴边的一列几乎都是表格列或字幕；组内项数只能 2~3。不要靠文字里有没有符号去排除——台词里什么符号都会出现。」**

### 常驻任务（TriggerTask）没有任何防重复点击

- 现象：判据一误命中，TriggerTask 就每 0.5 秒点同一处、永不停止，只能靠人发现。
- 根因：`_no_change` 看门狗只在 TrainingTask 的 flow 里，TriggerTask 没有。
- 提示词里应该加的那句：**「常驻任务必须自带『同一画面指纹连点 N 拍就存证+停手 N 拍』的保护，比赛内 HUD 这类本来就该连点的 handler 要豁免。」**

### 抽卡页动画期间的 OCR 结果不能直接采信

- 现象：扭蛋页卡片还在飞入/翻转时也能读出 3 张卡，脚本 0.3 秒就点「确定」，买下中间那张紫卡；1.7 秒后重进才看清同价位的金卡（防守增加++ / 80 币），等于白扔一次机会。
- 根因：`read_gacha_cards` 只靠「价格数字 + 卡名位置」定位，动画中间态同样满足；旧代码只处理了「读不到卡」这一种情况，读到但可能还在动的情况没管。
- 提示词里应该加的那句：**「抽卡/翻牌页必须先确认卡片稳定（连续两帧识别一致）再决策——『读不到』和『读到了但还在动』是两回事。」**

### 科目名被吞进旁边的「MAX」标签

- 现象：2026-10-29 第 4 周海边合宿星期三，日志候选科目里明明有「防守（小人）」，但整轮只探测了弹跳和运控，防守一次都没点；用户看到的是「有队友的防守训练被跳过了」。
- 根因：满级科目的按钮是「名字 + MAX」，OCR 把「守」和 MAX 糊成一个框，这一帧只剩「防」；`subjects_from_texts` 只会把**两个单字**拼回科目名，少一个字就返回空，`find_subject_box` 拿到 None 后 `continue`，**静默跳过，日志里连一行都没有**。
- 提示词里应该加的那句：**「OCR 对按钮文字的漏读要按『已知词表』补全：六个科目的首字/尾字都唯一，只剩一个字也能定位那一行；任何『找不到就 continue』的分支必须打告警，不能让科目静默消失。」**

### 购买次数不能当上限

- 现象：2026-10-29 游戏厅买了 237 次同一个「防守」小游戏，卡了 9 分钟，任务还停不下来。
- 根因：`handle_arcade` 没有「这一下到底成交没成交」的判断，零用钱读不到（`None`）时还被当成买得起；而卡死看门狗靠界面指纹，金额数字每拍都在变，签名一直变，永远判不出卡住。
- 提示词里应该加的那句：**「购买类流程不许用『一天买几次』当上限（羽漱川湊能买两次、卧云真昼能买升级版、白神时久有免费商品）；要判『成交没成交』——成交必然改变页面状态（零用钱变少/卡片消失），连续 N 次零用钱没变且还是同一件才算点不动。」**

### 「让路暂停」和「Alt 抢前台」不能同时成立

- 现象：2026-10-29 第一版「键鼠暂停」写完，用户反馈「还是抢鼠标」——暂停 5 秒到点后第一个动作就是 Alt 抢前台，人刚停手就被踢下焦点。
- 根因：本游戏只吃真实鼠标事件（`PostMessage` 实测无效），要点击就必须先把游戏置前，而置前就是拿走用户焦点。「暂停 N 秒」只是把「抢」往后推，不是不抢。
- 现在的做法：只看「用户最后一次输入距今多久」，静默满 3 秒才动手（配置项「空闲等待(秒)」）；**没有等待上限**，旧实现的 120 秒兜底会去抢正在操作的用户。Alt 注入本身也是系统输入事件，`ensure_foreground` 里必须 try/finally 记账，否则下一次动作会把脚本自己的 Alt 当成「用户还在操作」。
- 提示词里应该加的那句：**「让路类需求不许用『暂停 N 秒』实现，要改成『用户静默满 N 秒』；任何抢前台/注入输入的分支都必须纳入同一套记账，且不许设『等太久就强制恢复』的上限。」**

### 框架传参单位：task.swipe 的 duration 是毫秒

- 现象：2026-10-30 选队长翻页每次卡 6 分 42 秒，两次日志精确到 402 秒。
- 根因：ok/task/task.py 的 swipe(duration=0.4) 先算 ms = int(duration*1000) 再传给输入后端，而自定义的 GirlsInteraction.swipe 把第 5 个参数当**秒**用：12 步 × (400/12) 秒 = 400 秒。同一个仓库里 	ools/collect_ssr.py:Screen.swipe 直接调 mouse_event、不经过框架，所以「那边拖动正常」。
- 提示词里应该加的那句：**「自定义输入后端的方法必须和框架调用点对齐单位（毫秒/秒/秒×1000）；凡出现『同一操作某处慢、某处正常』，先拉出两条调用链看谁在做换算，再怀疑算法本身。」**

### 图像判据：纯占比会被零散噪声顶过阈值

- 现象：2026-10-30 周末地图，步行街上方其实没有队友气泡，但建筑阴影的深色像素占比 0.019 贴着 0.02 阈值，某一帧过线 → 判成「步行街和游戏厅都有队友」，按顺序选了没队友的步行街。
- 修法：enue_has_mate 增加「最大连通块占 ROI ≥ 0.05」（气泡是整块 0.12，阴影零散 0.018），并加色相约束（蓝紫 >=r 且 g<=b，排除绿色树影）。同一帧三处地点 0.12/0.15/0.018/0.000，分离度 6 倍。
- 提示词里应该加的那句：**「用像素占比判断『画面上有没有某个 UI 元素』时，必须再加形状约束（最大连通块、长宽比、边缘），否则阴影/高光/贴图噪声会在阈值附近随机翻转；阈值要落在实测两类样本的中间，并在注释里写清样本值。」**

### 顶栏数字「读不到」= 依赖它的判据全部静默失效

- 现象：2026-10-31 餐厅打工，顶栏实际是 23/130，日志里一直是 `精力 None`；
  写好的规则「精力不够右边那张（25）→ 改选左边不耗精力的」从来没生效过。
  同一条链上的扭蛋「清空精力」阈值、公园「野餐」阈值也一直是瞎的。
- 根因：`top_bar()` 是对**裁剪后的顶栏图**再 OCR。同一帧整帧 OCR 读到 `0/130`，
  裁剪重 OCR 读成 `301130` —— 斜杠被吃掉，`STAMINA_RE` 要求有 `/`，于是 None。
- 修法：`top_bar(texts=None)` 优先复用**整帧** OCR（`flow.run()` 存 `_tick_texts`），
  只按 top_bar 区域过滤；裁剪重 OCR 只当兜底。
- 提示词里应该加的那句：**「同一个数字既要 OCR 读得到又要正则匹配得上的时候，
  不要为了省时间去裁剪区域重新 OCR —— 小图上分隔符（`/` `-` `.`）最容易被吞掉；
  优先复用整帧 OCR 结果再按区域过滤。并且凡是 `xxx is None` 都要当告警打出来，
  否则依赖它的规则会静默失效，日志上看只会觉得『规则没生效』。」**

### 二级确认页上的「前往XXX」可能是灰的，不能连点

- 现象：2026-10-31 餐厅，弹窗写着「精力不足 ⚡25」，「前往当服务员」是灰的；
  旧 `handle_activity_go` 无条件点，连点 4 分钟（100+ 次）。
- 为什么全局防卡死没救下来：`_no_change` 按**整页指纹**算，而 OCR 每拍都有细抖动
  （同一个气泡被读成「推荐❤体能 / 推荐体能」）→ 计数被反复复位，
  连「3 轮点不动就停任务」都没触发。
- 修法：`handle_activity_go` 两级判据 —— 按钮附近有「精力不足/无法选择/不可」→ 不点；
  同一个「前往」点过一次画面文字没变 → 不点。两种情况都关掉弹窗、
  把这张卡记进 `blocked_activities()`（当天不再选），回卡片页改选另一张。
- 提示词里应该加的那句：**「点『前往/确定/开始』这种『进入游戏』的按钮之前，
  必须先读按钮附近的『不足 / 不可 / 未满足』提示；同一个按钮连点两次画面没变化
  就要换策略（退出 → 改选），不要指望全局卡死检测 —— 它按整页指纹算，

### 「出行」这类两字按钮不能用 `click_text`：会点到对话台词，还顺手把当天机会用掉

- 现象：2026-10-31 18:50 那局，训练日主界面本来有「出行」入口（野上泷周五/额外周末），
  结果一次都没点到，直接进了训练。日志：
  `left_click 今天可以出行哦！要不 (950, 182)` → `训练日有「出行」入口 → 先外出` →
  下一拍 `left_click 训练 (1378, 750)` → `体力 130，进入训练科目`。
- 根因：①`click_text("出行")` 是**包含匹配**，先命中对话框里的台词
  「今天可以出行哦！要不…」（cx≈0.50, cy≈0.17），右侧按钮一下没点；
  ②`outing_done = True` 写在点击**之前**，点空也算「今天用过了」，
  下一拍 guarded 分支直接跳过，掉进 else 去点「训练」。
- 修法：判据收进 `parsers.find_go_out_button`（只认**整词**「出行」，
  多个候选优先右下 `go_out` 区域，OCR 拆字时把「出」「行」拼回去），
  周末首页和训练日主界面共用；`outing_done` 改成**点到按钮之后**才置位，
  只有台词、没有按钮时那拍只推进对话。
- 提示词里应该加的那句：**「按钮类判据只认整词，`click_text` 的包含匹配会命中对话台词
  （`left_click 今天可以出行哦！要不`）；一次性的动作标记必须等点击真正落地再置位，
  否则一次空点就把当天机会烧掉，流程会『默认』走另一条分支。」**

### 地点内页判据被「地图上的奖励提示」抢走：进了地图又退出来

- 现象：2026-10-31 19:33（第3周 星期五，野上泷额外周末）出行进地图后立刻退回训练日
  主界面，然后点了训练。日志：
  `left_click 出行 (1374, 464)` → `训练日有「出行」按钮 → 先外出` →
  OCR 地图页 `游戏厅/属性+/公园/精力+/餐厅/零用钱+/扭蛋增强/步行街/随机增益+` →
  `扭蛋：三张卡都没认出来，退出不买` → `left_click 训练 (1377, 750)`。
- 根因：`handle_street` 的判据是 `STREET_TITLE = ("请选择1个扭蛋", "扭蛋")`，包含匹配；
  这次地图上步行街的奖励提示写的是「**扭蛋增强**」（平时是「零用钱+」，因为野上泷的
  「扭蛋加成」技能），于是**地图**被判成扭蛋页 → 读不到三张卡 → `leave_street()` 返回。
  更糟的是 `mark_visited("步行街")` 在退出前就写了，回来以后当天再也不进步行街。
- 修法：`handle_street` 里加「地图上有 ≥2 个地点名 → 不是扭蛋页」的门，且放在
  `mark_visited` **之前**。同款风险：任何 `地点内页` 的判据词如果同时出现在地图的
  奖励提示里（属性+/精力+/零用钱+/扭蛋增强…），都会被抢。
- 提示词里应该加的那句：**「地点内页的判据要能区分『地图』：地图上同时有多个地点名和
  各自的奖励提示（零用钱+/扭蛋增强…），任何只靠单个关键词的判据都会被这些提示词抢走；
  而且 mark_visited 必须放在确认真的是内页之后。」**

### 彩框判据被「选中行噪声」顶过门限：一帧只有 1 个彩框，日志报了 2 个

- 现象：2026-10-31 19:51，用户在实机上看到科目页只有「投射」带彩虹边，日志却是
  `当前已选「投射」…彩虹 1｜得分 4.30` + `探测「弹跳」…彩虹 1｜得分 4.30`，
  两个科目平分，按「当前值低」选了弹跳，把真彩框（而且还是 `满经验 1`）挤掉。
- 根因：`has_crit_border` 的采样半窗 ±0.06h 比科目行距（≈0.10h）还大，选中行的
  图标/高亮会蹭进上下环带；实测同一行「未选中 0.094 → 被点开成选中行 0.214」，
  旧门限 0.20 刚好被顶过。真彩框其实在 0.51~0.56，跟噪声差一个量级。
- 修法（2026-10-31）：半窗 ±0.06h → **±0.050h**（再窄到 0.045h 会把真边框切掉，
  真彩框掉到 0.09~0.16），门限 0.20 → **0.22**，并补「高于其它行最低值 ×2」的相对条件。
  存盘帧上复核：真彩框 0.27~0.39 / 噪声 0.00~0.11，分得开。
- 可复用的工具（都在 `logs/`，被 gitignore）：`_crit_frame.py`（逐行复算占比）、
  `_crit_calib.py`（同一帧比不同半窗）、`_verify_crit.py`（用真实代码重跑判定）。
- 提示词里应该加的那句：**「彩色边框/高亮这类像素判据，报出来之后要拿存盘帧复算一遍
  （同一帧逐行占比 + 真值目视），别把『选中态』当特征：选中行的渲染和未选中行不一样，
  采样窗一旦大于行距就会串色。另外这类边框会**闪**（同一科目不同帧 0.157 / 0.318 / 0.343），
  单帧占比只能当下界 —— 拿一批『强彩框』样本定出来的门限，必然会把弱彩边漏掉。」**
