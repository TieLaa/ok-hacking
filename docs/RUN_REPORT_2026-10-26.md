## 2026-10-26 09:30 用户复盘后的 6 条修正

### 1. 体力规划：失败率超限直接休息

科目页读到当前科目失败率 > 上限（默认 50%）时，**不再"继续练、只打日志"**，
而是 `_force_rest=True` + 点右上角返回 → 训练日主界面强制点「休息」。
之前的表现是体力 7、失败率 77% 还在硬练。

### 2. 休息确认框：必须点「确定」

弹窗正文「休息需要一整天，可恢复体力，是否要休息？」的按钮是 `[休息] [取消] [确定]`。
旧 `handle_popup` 用 `("今日不再提示","关闭","取消")` 匹配，正好命中「取消」，
于是「点休息 → 弹确认 → 点取消」死循环，整周体力不动。
现在 `handle_rest_confirm` 排在最前，整词匹配「确定」（退路是「休息」）；
`handle_popup` 里的「取消」也只在**没有确定按钮**时才点。

### 3. 购买逻辑：默认只买器材手册+

新增配置 `购买策略`：只买器材手册+ / 买最贵 / 不买，默认**只买器材手册+**。
训练流不再「有钱就买」——器材熟练度满才出满经验暴击，其他钱留给周末的黄色道具。
商店也只在 `商店流` 的周末进（`周末先看商店` 不再是所有流派的通用行为）。

### 4. 周末路线：训练流先步行街 → 游戏厅 → 公园

- `STYLE_PLACES["训练流"] = ["步行街","游戏厅","公园"]`；`周末第一天优先资源点`
  打开时，周六按这个顺序找地点，周日强制回公园补精力。
- `weekend_priority()` 会滤掉地图上没有的「商店」，公园永远兜底。
- 步行街扭蛋加了体力闸：训练流体力 ≥ 休息阈值时**不抽**（抽了清空精力，第二天没法练），
  体力低时才抽，符合「低精力抽到清空精力的高品质扭蛋是赚的」。
- **这一条还没实机验证**：步行街/游戏厅的内页（尤其是「黄色道具」的购买界面）
  没有截图，`允许进步行街 / 允许进游戏厅` 默认仍是 False。开这两个开关前建议先跑一个周末，
  让 `logs/unknown/` 把内页存证下来，再补「有队友加成的黄色道具」的判据。

### 5. 科目评分改成显式权重

`subject_score()` 按用户给的分数直接加，不再用「主项 +2 / 彩虹 +1」这种拍脑袋系数：

```
队友 ×1.0 + 道具 ×1.1 + 经理 ×1.2
+ 黄框道具暴击 ×1.2 + 经理暴击 ×1.3 + 彩色道具暴击 ×1.3
```

- 经理：场景名字牌是「球队经理」，会被 OCR 当成队友名，`read_scene()` 单独扣出来；
- 黄框道具：`count_gold_cards()` 用 HSV 金色直取（H 12~45 / S>120 / V>180），
  实测 `subject-crit.png` 能稳定找到 156x167 那张金牌器材；
- 彩色道具暴击：沿用已验证的 MAX 满经验；
- 经理暴击：经理在场且这次确实出暴击（有满经验或彩虹边框）。
- 已知限制：角色名 OCR 经常漏（`subject-crit.png` 里「闪堂」整条没识别出来），
  队友数会偏少，这一项仍是单帧读取。

### 6. 紧急停止热键（新增模块）

`src/util/emergency_stop.py`：独立线程 `RegisterHotKey + GetMessageW`，
命中后只置 `threading.Event`，`TrainingTask.run()` 每拍检查，命中即退出并通知。
候选顺序 `F12 → F8 → Ctrl+Alt+F12 → Ctrl+Shift+F12`，抢到哪个写日志。

- 实测本机 **F12 已被别的程序占用**（`RegisterHotKey` 返回 1409），最终抢到 **F8**；
  `tools/test_hotkey.py` 用 `keybd_event` 模拟按键，能收到 `WM_HOTKEY` → **PASS**。
- ok-script 自带的 `Start/Stop`（默认 F9）仍然保留，但它和 ok-ef 这类程序会抢同一个键，
  且依赖 GUI 线程轮询；两个键互为备份。
