## 四、5 秒卡死判定

- 任务内看门狗：`卡死判定(秒)=5`，判据是**「界面文字指纹没变」且「距上次点击 ≥ 5 秒」**。
  只看指纹会误判剧情 ▼ 连点（文字不变但点击在推进，15:45 那段就是），所以两个条件必须同时满足。
- 触发后：`dump_debug()` 存截图 + OCR + 最近动作到 `logs/debug/<时间>_stall5s/`，然后点屏幕中央继续；
  连续 3 轮仍不动才停任务。
- 外部观察器 `tools/watch_run.py` 用同一口径旁路观察（只读文件，不点击、不截图），
  结果：`stall_count = 0`，`reason = task finished`（`logs/run_session/summary.json`）。
- **本轮没有触发过**，所以真实触发路径只有 4 条看门狗单测覆盖，没有实机样本。

## 五、发现的问题（按优先级）

1. **60% 的点击是「屏幕中央」盲点**（489/814）。`logs/unknown/` 里 90 张存证大多是两类：
   训练日主界面过渡帧（顶栏已有「第N周/星期X/体力」，按钮还没渲染）和训练加成动画（「心·技·体」）。
   现在靠盲点也能过，但一步一存证、一步一点，是 703 步的主要来源。补两个 handler 能把步数砍一半。
2. **扭蛋买完会误报「三张卡都没认出来，退出不买」**（15:48:20、15:54:01、15:55:30 共 7 次）。
   看零用钱能对上：15:48 有 150 → 选 100 币 → 之后 120（+70 收入），说明**购买其实成功了**，
   是买完之后页面变了、`handle_street` 又跑一拍读不到卡，于是误判并退出。日志需要区分「买完退出」。
3. **商店逻辑本轮零验证**：零用钱始终 < 300，`handle_daily_shop` 一次都没进店。
4. **比赛没有胜负日志**：只有「尝试跳过比赛 / 跳过不可用」，报告拿不到战绩。建议结算页加一行
   `比赛结果：胜/负 + 比分`。
5. **启动瞬间一条 ERROR**：`Selected capture method is not supported by the game or your system!`
   （15:44:48，随后自动恢复，不影响运行）。每次启动都会出现，属噪声，值得查一下是不是窗口瞬间
   `visible=False` 导致的。
