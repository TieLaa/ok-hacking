## 一、验证清单（按优先级）

### 1. 彩框数据（最高优先级）

- **为什么**：彩框权重 2.3 目前**没有任何实测**，历史上被统计进「无框」组。
- **注意（2026-10-31）**：判据刚重标定过（半窗 ±0.050h + 门限 0.22 + 相对最低行 2 倍）。
  之前按旧判据（±0.06h / 0.20）记下的彩框样本**可能混了假阳性** —— 用户当场发现
  一帧只有 1 个彩框却报了 2 个（弹跳 0.214 是选中行噪声）。
  复核办法：`python logs/_verify_crit.py logs/debug/<帧>.jpg`（用真实代码重跑判定）。
- **怎么做**：正常跑一局，日志里现在会打 `选科目「…」…｜金框 0｜彩虹 1｜…`。
- **通过判据**：出现至少 1 次 `彩虹 1`；记录该次的实际属性增益。
- **目标**：累计 10+ 个彩框样本，才能给出 2.3 是否合理的结论。

### 2. 权重复核（2.1/2.2/2.3 vs 10/30/40）

- **为什么**：实测金框 +32（回归）~+52（原始差），经理 +7~+13，按「1 分 = 1.15 点」折算应是经理 ~10、金框 ~30，比现在的 2.1/2.2 大一个量级。
- **怎么做**：跑完后执行

  ```powershell
  .venv\Scripts\python.exe tools\check_training_gain.py
  ```

- **通过判据**：输出的信号表与 `docs/REVAMP_PLAN.md` 第七节的结论方向一致（金框 >> 经理 >> 队友/装备）。
- **注意**：原始差会被「器材等级」污染（满经验的卡本身等级更高），所以只看**方向**，不要直接拿原始差当权重。

### 3. 金框阈值在度假页的表现

- **为什么**：金框用同屏相对亮度（>0.10 且 >1.5× 中位数），只在合成像素上验过；第 4 周海边合宿整屏偏黄，是唯一能证伪的场景。
- **怎么做**：跑到第 4 周度假时抓一帧存 `docs/shots/<日期>-vacation.png`。
- **通过判据**：未选中的科目行**不应**被判成有金框；日志里 `金框 1` 的次数与现实相符。

### 4. unknown 兜底占比（改版前的基线数字）

- **为什么**：unknown 占比越高，「没坏」的置信度越低；改版后要拿它做对比。
- **怎么做**：跑完统计

  ```powershell
  Get-ChildItem logs\unknown\*.txt | Measure-Object | Select-Object Count
  ```

- **通过判据**：记录一个数字即可（当前约 40~50%+，集中在训练加成/Bonus/升级浮层）。

### 5. 商店 5 件与第二行

- **为什么**：`docs/shots/` 里只有 4 件的老帧；第二行价格实测 y=0.746，离旧上限 0.75 只有 4px。
- **怎么做**：进店时看日志：

  ```
  商店：器材手册+(紫/100)、弹跳教科书(紫/100)、……
  ```

- **通过判据**：能列出 **5 件**，且第二行的商品也在列表里（尤其价格 > 0 的那件）。
- **顺手**：抓一张 1920×1080 的 5 件商店帧存 `docs/shots/<日期>-shop5.png`。

### 6. QuickMatchTask 真机一局

- **为什么**：修复（同画面连点 3 拍停手）只做过离线验证，没进过真实比赛。
- **怎么做**：任务页启用「快速比赛」（默认关闭），手动开一局比赛。
- **通过判据**：能跳过/点 ▶▶/收结算，且**不会**在同一处连点（曾出现全中「对手实力」点 30 秒）。

### 7. 日期跳变观测（为改期角色铺路）

- **为什么**：改期角色入队后，训练日也有出行、周末也能训练；跳转按钮会不会改顶栏日期还不知道。
- **怎么做**：不用特意做，正常跑；代码已经在日期键变化时打日志：

  ```
  日期键 (3, '六') → (3, '日')（今日行程重置）
  ```

- **通过判据**：正常跨天时这条日志出现且符合预期；如果同一周内出现**倒退或跳变**，把前后两个键记下来。
