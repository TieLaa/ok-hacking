# 审核清单：流派自动识别 + 周五/周六/周日出行（2026-10-29）

> 用户口径：「因为逻辑互斥而修改的代码要记录一下让我审核」。
> 本文只列**旧行为被新规则顶掉/改掉**的地方，逐条给出证据和代码位置。
> 规则全文进 `docs/RULES.md`（第 0 / 1 / 1.1 / 6 节）。

## 一、必须改的互斥点

### 1. 「商店流周六也逛店」被「周六所有人不逛店」顶掉

| | 旧 | 新 |
|---|---|---|
| 谁进店 | 只有商店流；周六、周日各一次 | 训练流 + 商店流；**只有周日**一次 |
| 周六 | 商店流先进店再出行 | 所有人直接出行（其他流派去餐厅打工） |

- 位置：`handlers/weekend.py::handle_go_out`
- 互斥原因：新口径里周六其他流派的时间被餐厅打工占满；再进店等于多花一天。
- 改法：进店条件从 `style == "商店流"` 改成 `day == "日" and style in ("训练流", "商店流")`。
- 旧测试 `test_saturday_enters_shop` 已删除，换成 `test_saturday_does_not_enter_shop`
  （四种流派都断言点「出行」）。

### 2. 「周日训练流固定公园」从特判改成查表

- 位置：`handlers/weekend.py::handle_weekend` + `flow.weekend_priority`
- 旧：`if style == 训练流 and 周末第一天优先资源点 and day == 日: places = ["公园"]`
- 新：`WEEKEND_PLAN[(day, style)]` 表，周日训练流就是 `["公园"]`。
- **行为等价**（默认开关下），但开关「周末第一天优先资源点」从此不再生效 ——
  周日的地点由表固定，不再受配置影响。配置项保留（读旧配置不报错），描述里已标注。

### 3. 周末出行顺序整体改成「星期 + 流派」查表

- 位置：`flow.weekend_priority(day)`、`constants.WEEKEND_PLAN`
- 旧：`STYLE_PLACES[style]`（训练流 步行街→游戏厅→公园；扭蛋流 步行街→公园；
  商店流 商店→公园；小游戏流 游戏厅→公园），周六周日共用一张表。
- 新：周六/周日分别查表；`STYLE_PLACES` 只在**读不到星期**时兜底。
- 互斥点：旧表把「周末两天」当同一套行程，新规则两天完全不同，无法共用一张表。
- 影响：扭蛋流/小游戏流周日不再有「公园兜底」这一站（除非对应开关关闭）。

### 4. 周五休息阈值按流派分档

- 位置：`flow.rest_threshold(day)`、`handlers/training.py::handle_training_day`
- 旧：所有流派 `体力 < 休息体力阈值(40)` 就休息。
- 新：周五 → 训练流 40（不变）；其他流派 55；商店流 80。其余日子不变。
- 互斥点：同一天不同流派阈值不同，旧代码只有一条 `limit`。

### 5. 餐厅选项：训练流保留配置，其他流派改成「队友多 / 平局选右」

- 位置：`handlers/weekend.py::handle_restaurant` + 新增 `restaurant_order`
- 旧：所有流派都按配置「餐厅选项」（默认当服务员）。
- 新：训练流仍按配置；其他流派按（队友数降序, x 坐标降序）选。
- 互斥点：配置项和「队友多优先」可能给出相反答案，必须明确谁优先 —— 训练流用配置，
  其他流派用队友数。

### 6. 训练计划（日历）页从「被地点 handler 误吃」改成专属 handler

- 位置：新增 `handlers/training.py::handle_training_plan`，注册在所有地点 handler **之前**。
- 旧：日历页同时含「转动扭蛋」「野餐」「划船」，被 `handle_street` 认成扭蛋页
  → 点右上角退出（还 `mark_visited("步行街")`，导致当天少去一个点）；
  2026-10-27 15:17 那局被 `handle_park` 点了「野餐」。
- 新：识别「的训练计划」→ 读队长 → 定流派 → 关掉日历。
- 互斥点：日历页和扭蛋页/公园页共用「扭蛋」「野餐」这些词，靠**顺序**区分。
- 证据：
  - `logs/unknown/1029-093636_register_stuck_s636.txt`（名字框 + 标题框坐标）
  - `logs/ok-script.2026-10-27.log` 00:54:16（被当成扭蛋页）
  - 同上 15:17:26（被当成公园页）

### 7. 新增：流派未知时点一次左上角

- 位置：新增 `handlers/training.py::handle_style_probe`，注册在训练日主界面之前。
- 这是**新增的两次点击**（开日历 + 关日历），只在「流派=自动」且变量为空时发生。
  配置里选具体流派 = 手动锁定，训练流回归跑不会多这两下。

## 二、行为等价性

- 训练流 + 「流派=训练流」手动锁定：周六 步行街→游戏厅→公园、周日公园（划船/野餐）、
  周五 40 阈值、不进店、科目/比赛/商店/扭蛋/游戏厅判据全部未动。
- 训练流 + 「流派=自动」且队长是训练流角色：多两次点击（日历开/关），其余同上。
- 唯一与旧版不同的训练流细节：日历页出现时不再误记「步行街已去」、不再误点「野餐」。

### 7.1 因此作废的配置项（不是删掉，只是不再生效）

| 配置 | 为什么作废 |
|---|---|
| `周末先看商店` | 新口径把「先逛店」绑死在**周日 + 训练流/商店流**，这个开关没有可表达的空间 |
| `周末第一天优先资源点` | 周日地点由 `WEEKEND_PLAN` 表固定（训练流=公园），开关多余 |

两项都保留在 `default_config` 里（读旧配置不报错），描述已标注「已作废 / 不再生效」。

## 三、待实测（我第一次跑就盯着这几条）
1. **餐厅内页判据**：没有实测帧。「队友数」用橙色小人连通域来数，需要第一次实跑看日志
   `餐厅：队友数 当服务员=x、桌游GM=y`；如果两个都恒为 0，说明这一页不是那种头像，
   要换成文字/立绘判据（届时只改 `restaurant_order` / `mates_near`）。
2. **左上角按钮**：`handle_style_probe` 点的是 (0.035w, 0.06h)，依据是 `flow.exit_page`
   docstring 里记的「训练日左上角打开训练计划」。第一次跑要确认它真的开了日历，
   而不是返回大厅。
3. **队长名 OCR**：日历只显示姓氏（真崎/佐久间/望月），已按前缀匹配；日志会打
   `训练计划：队长「XX」→ 流派「XX」`。
4. **周五阈值**：需要一局跨到周五才能碰到，日志会打
   `体力 x < 55（扭蛋流·星期五）→ 休息`。
