## 术语：专注 / 精力（2026-11-02 规范用词）

顶栏只有**一个数字**，按界面语境叫两个名字，别再混用「体力」：

| 名字 | 语境 | 含义 | 实现 |
|---|---|---|---|
| **专注** | 大厅 | 每日限量的资源。开训练要扣它；不够时游戏弹「训练所需专注还差 25，是否进行回复呢？」 | `top_bar()` 的 `stamina`、`flow.rest_threshold` |
| **精力** | 训练内 | 随活动变动的资源：训练科目、打工、公园野餐、扭蛋「清空/消耗所有精力」 | 同一个数字，但判据与日志用「精力」：`休息精力阈值`、`扭蛋清空精力阈值`、`WORK_STAMINA_COST` |

- 游戏原文只出现过「专注」（大厅开训练，`logs/debug/1027-192726_nochange3/ocr.txt`）和
  「精力」（训练结算「精力降低了X」、休息确认「可恢复精力」、扭蛋「消耗所有精力」），
  **没有「体力」**。OCR 判据里保留的「恢复体力 / 体力不足」只是旧文案别名，不是术语。
- 配置项跟着改名：`休息精力阈值`、`扭蛋清空精力阈值`。旧配置里的「体力 / 专注」键由
  `config_spec.migrate_saved_config()` 在 `load_config()` 之前搬过去，值不丢。
- 2026-11-02 之前的日志与 `docs/RUN_REPORT_*` 里写的是「体力」，读老记录时按上表换算
  （大厅语境 → 专注，训练语境 → 精力）。

## 0. 流派：只由队长决定（2026-10-29）

实现：`flow.style` / `flow.reset_style` / `flow.resolve_style` / `handle_style_probe` /
`handle_training_plan` / `parsers.style_for_name`

**流派不是配置项，是队长的属性。** 本任务只负责「快速接手」这一条：

| 流程 | 怎么定流派 |
|---|---|
| 快速接手（本任务） | 流派为空 → 进训练后在训练日主界面点一次左上角打开日历 → 读「XX的训练计划」→ 查表写入 |
| 全自动（另一条流程，尚未实装） | 它自己把流派写进 `_style`（`run()` 之前），本任务看到有值就不再点日历 |

| 时机 | 行为 |
|---|---|
| `run()` 开始 | `resolve_style()`：配置里有队长 → 查表定流派；配置为空 → 清空流派等日历 |
| 点「开始训练」 | `reset_style()` 清空流派（新的一局，队长可能换了），选中的队长匹配配置则再套用配置流派 |
| 训练日主界面 + 流派为空 | `handle_style_probe` 点左上角 (0.035w, 0.06h) 开日历，最多 3 次、3 秒冷却 |
| 日历页 | `read_plan_captain` 取左上角名字（只显示姓氏，按前缀查表）→ 写入 `_style` → 点右上角关掉 |
| 查表查不到 | 按「训练流」跑并告警，不再反复开日历（SR/R 卡还没收录） |
| 还没定下来之前 | `style` 一律返回「训练流」（最保守） |

- **队长的唯一来源是监控页的「指定队长」勾选框**（2026-11-01）。
  配置里有队长就按它定流派，**不管这一局是不是从大厅开的**。
  - 旧逻辑只在 `is_lobby()` 时套用配置队长，理由是「接手别人的局时实际队长可能不是
    配置里那个」。但**日历只在训练日弹**：接手的局如果当前是周末（非训练日），
    就永远读不到实际队长 → `_style` 一直空着 → `style` 兜底成「训练流」→
    **扭蛋流跑成训练流**（2026-11-01 19:19 实跑日志：
    `非大厅开局 → 流派以游戏内队长/日历为准` + `流派：训练流（待日历识别队长）`）。
  - 现在由 `flow.resolve_style()` 统一决定：配置里有队长 → 查表定流派（查不到才回落到日历）；
    配置为空（无队长模式）→ 清空流派，等日历认实际队长。
- 角色表 `STYLE_BY_NAME` 抄自 `docs/roster/ssr_roster.json` 的 `style_tag`（18 个 SSR）。
- **名字比较一律过 `Defs.norm_name` / `Defs.name_matches`**（2026-10-31）：游戏里读到的名字
  和表里的写法不一样 —— 实测 `SR-亚理纱贾斯敏` vs 表里 `亚理纱·贾斯敏`（间隔点被 OCR 吃掉、
  底部名字行还带稀有度）。旧判据 `want in name` 直接比字符串，16 张队长卡全被当成「不是她」，
  最后报「队长池里没有」并停任务（`logs/mcp/sento_summary.txt`）。同一套归一化也用在
  `style_for_name` / 监控页下拉回填 / `_style_from_config`。
- 日历页有专属 handler，**必须排在所有地点 handler 之前**：这一页带「野餐/划船/转动扭蛋」，
  旧版被 `handle_street` 抢走（2026-10-27 00:54 误当扭蛋页退出 + 误记「步行街已去」）。

## 0.5 无队长模式：不接开局（2026-10-31）

实现：`flow.no_captain_mode` / `flow.stop_for_no_captain` / `handle_lobby`、`handle_training_entry`、
`handle_captain`、`handle_team`、`handle_note_select`、`handle_equipment`、`handle_confirm_team` 的闸门

**`指定队长` 留空 = 无队长模式**（配置项 `无队长不接开局` 默认开）：

| 场景 | 行为 |
|---|---|
| 当前在训练日主界面 / 科目页 / 比赛等**已有局** | 照常跑，和以前一样 |
| 遇到大厅 / 训练剧本 / 训练核心（选队长）/ 选择队友 / 选择笔记 / 选择器材 / 确认编队 | **不点任何东西**，记一条告警后停止任务 |
| 勾选队长（填了名字） | 恢复自动开局：启程 → 按名字选队长 → 队友 → 笔记 → 器材 → 开始训练 |

理由（用户 2026-10-31）：这些页面不点就进不去训练，没法真的「跳过」；
所以无队长时不替你开局，只跑你手动开好的局，一局结束回到大厅就停。

- 监控页的「指定队长」勾选框就是切换这个模式：取消勾选 → 清空 `指定队长`
  **并清掉运行期的流派**（`task._style`）。
  勾选框**默认不勾**（2026-11-01）：旧版默认勾上，而下拉第 0 项是「── 训练流 ──」
  分组标题 —— 用户一进页面就等于「指定了第一个训练流角色」，扭蛋流被写成训练流。
  勾选时用下拉**当前**选中的角色，不是「列表第一个」。
- 回归桩（`tools/check_handlers.py`）把 `无队长不接开局` 设成 `False`，保持旧的自动选人流程可测。

## 1. 周末地点：按「星期 + 流派」排（2026-10-29）

实现：`flow.weekend_priority` / `constants.WEEKEND_PLAN` / `handle_weekend` / `handle_go_out`

| 星期 | 流派 | 去哪（顺序 = 优先级，前一个走完再下一个） |
|---|---|---|
| 周六 | 训练流 | 步行街 → 游戏厅 → 公园；**步行街/游戏厅谁名字上方有队友气泡就先进谁**（2026-10-30） |
| 周六 | 商店流 / 扭蛋流 / 小游戏流 | 餐厅（打工） |
| 周日 | 训练流 | 公园 |
| 周日 | 商店流 | 餐厅（打工） |
| 周日 | 扭蛋流 | 步行街 → 餐厅（先花钱，再打工） |
| 周日 | 小游戏流 | 游戏厅 → 餐厅（先花钱，再打工） |

- **商店**：只有**周日**、而且只有训练流 / 商店流，才在周末首页先点「商店」再点「出行」
  （`handle_go_out`）。周六一律不进店；其他流派直接出行。一天只进一次（`shop_checked`）。
- **别把地图当内页**（2026-10-31 实跑）：地图上除了地点名还有各自的奖励提示
  （属性+ / 精力+ / 零用钱+ / **扭蛋增强**）。只靠单个关键词的内页判据会被这些提示抢走 ——
  `handle_street` 就曾因为地图上的「扭蛋增强」把地图判成扭蛋页，进去读不到卡就退出，
  当天的出行白跑。现在判据里加了「地图上 ≥2 个地点名 → 不是内页」的门，
  且 `mark_visited` 必须放在确认真的是内页之后。
- 一天只进一个地点；进了发现不合适就退出，**当天不再重复进同一个地点**
  （`weekend_state["visited"]`）。
- 某个地点没开（配置开关关闭）就从顺序里过滤掉；过滤空了退化成公园（`weekend_priority`）。
- 读不到星期（顶栏 OCR 失败）时按**周六那一行**兜底（每个流派都有定义）。
- **队友气泡**（2026-10-30）：周末地图上每个地点名字上方有个深色对话气泡 + 队友头像。
  训练流周六在步行街/游戏厅之间比较，优先级：
  1. 只有一个有队友 → 去有队友的；
  2. 都有队友 → 再比**打折**（地点名左侧红色大号「打折」），只有一个打折就去那个；
  3. 都没有队友 / 分不出高下 → 保持原顺序。
  判据都是「界面事实」不是 OCR 猜词：队友 = `BaseGirlsTask.venue_has_mate`（深藏青像素占比 ≥ 0.02，
  标定：有气泡 0.052~0.096、公园 0.0010）；打折 = `venue_on_discount`（OCR 到「打折」且框在名字左侧同一行）。
- **隐藏规则**（2026-10-30 用户口述）：在步行街买扭蛋 / 在游戏厅玩小游戏，**当天就结束**，
  所以这两处是二选一；某些角色能突破（例：羽漱川湊 游戏厅可买两次）。

## 1.1 餐厅打工的选项（2026-10-29，通用）

实现：`handle_restaurant` / `restaurant_order` / `option_selectable` / `card_stamina_cost`

| 顺序 | 规则 |
|---|---|
| 1 | **能选的优先**：卡片附近写「精力不足 / 无法选择 / 不可」→ 不可选；卡片标的消耗 > 当前精力 → 不可选 |
| 2 | 可选的两张里：**队友多**的优先（卡片左上角的队友小头像，橙色连通域 + `mates_on_card`） |
| 3 | 队友一样多 → 选**右边**那张（消耗精力的） |

- 右边的默认消耗按 `WORK_STAMINA_COST`（25）估，左边按 0（左边不耗精力）；卡片上写了消耗以卡片为准。
- 「精力+30 / 精力恢复」这类是收益，不会被当成消耗。
- 数不到头像就都算 0 → 顺序退化成「右边优先」，等于用户给的平局规则。
- ⚠ **队友个数还数不准**（2026-10-31 实测 `docs/shots/restaurant_cards.png`）：
  餐厅两卡的队友标记是「深蓝底 + 头像」的整块气泡，`mates_on_card` 的兜底判据只能给
  「有 / 没有」（0 或 1），左卡实际 2 人、右卡 1 人，读出来都是 1 → 平局 → 选右边。
  要真数出个数，得按气泡宽度/头像宽度做标定，需要更多样本；在那之前，
  靠精力门槛兜底（精力不够右边时仍然会选左边）。
- **精力读的是整帧 OCR**（`top_bar(texts)`，2026-10-31 改）：裁剪顶栏重 OCR 会把
  `0/130` 读成 `301130`（斜杠被吃掉）→ `stamina=None`，这条规则就静默失效了。
  那一天实跑：精力 23/130 仍然去点 25 的「当服务员」，卡在灰掉的「前往」上 4 分钟。
- **卡片页本身不显示精力消耗**（2026-10-31 实测帧 `docs/shots/restaurant_cards.png`）：
  只有进了详情弹窗才看得到「精力不足 ⚡25」。所以 `handle_activity_go` 必须兜底：
  弹窗说不足 / 同一个「前往」点了没反应 → 关弹窗 + 把这张卡记进
  `blocked_activities()`（当天不再选），回卡片页改选另一张（桌游GM 不耗精力）。
  两张都点不动才退出餐厅。


## 2. 扭蛋（步行街）

实现：`handle_street` / `read_gacha_cards` / `card_band_quality`

| 条件 | 行为 |
|---|---|
| 品质是蓝/其他 | 不买 |
| 品质 **彩/金/紫** | 候选；分数按配置 `扭蛋品质优先`（默认 彩 400 / 金 300 / 紫 200） |
| 同分（= 同品质、同恢复） | 先「增强款」，再「有队友加成」，最后「便宜的」 |
| 名字带「+」 | **不算分**（用户 2026-11-02）：「+」只代表**同名卡片**之间的档位差，没「+」的同名卡本来就是紫/蓝，已由品质体现 |
| 效果是「清空/消耗所有精力」且精力 ≥ 30 | 不买 |
| 效果是「清空/消耗所有精力」且精力 < 30 | 可以买（拿精力换属性） |
| 效果是**恢复精力**（见下） | 按「本次能补上的精力」折半加分，满精力不加分 |
| 零用钱 < 卡片价格 | 跳过，看下一张 |
| **读不到价格**（价格数字还没渲染出来） | 不买，继续等；等不到就退出 |
| 读不到卡片（开局动画/页面切换） | 原地等最多 3.2 秒（0.8s×4）重试，仍空才退出 |
| 所有卡片都不满足 | 点右上角返回，**不点确定** |

阈值 `扭蛋清空精力阈值` 默认 30（`default_config`）。

### 卡面特征（2026-11-02 01:08 实拍，1549x871）

帧：`logs/events/1102-010859_gacha_teammate_middle.jpg`（第6周 星期日，105/130，471 币，
三张卡 70 / 90 / 50 全打折）。用线上同一份 `TrainingParsersMixin` 跑这一帧的实测值：

| 特征 | 取法（代码位置） | 实测 |
|---|---|---|
| 品质 | 标题带 y 0.36~0.43 的色相中位数（`card_band_quality`） | 左紫 hue 135 / 中金 hue 20 / 右蓝 hue 102，与判据完全对得上 |
| 队友标记 | 卡头左上 x(cx−0.12~cx+0.02) × y 0.22~0.36 的**深蓝块**（`has_mate_badge`） | 只有中间金卡命中：blob 137x51 px、均色 BGR(134,90,74)=#4A5A86、中位 HSV 112/117/137；左紫卡、右蓝卡都是 False |
| 队友档次 | 卡内说明文字 | 「队友属性**大幅**提升」> 中幅 > 小幅，三档只差在说明里，卡面没有别的视觉区分 |
| 「增强款」斜标 | 卡头 y 0.24~0.35 的「增强」字样 | 这一帧三张都没有 |

中间那张完整特征：`随机加成`、金色、100→90 币、说明「训练主力随机一项属性+80，队友属性大幅提升」、
带队友徽章，**名字里没有「+」**。

**2026-11-02 01:07:59 实跑买错**（用户当场指出「没有选到中间的队友扭蛋」）：
日志 `随机加成(金·+队友/90币/200)、体能增加++(金/90币/201) → 选「体能增加++」`。
识别没错 —— `has_mate_badge` 这一帧就是 True/False/False —— **错的是排序口径**：
旧版给名字带「+」的卡 +1 分，金卡之间「++」永远压过「队友」。已修：
名字里的「+」不进分（它只表示同名卡片之间的档位，没「+」的同名卡是紫/蓝，
品质已经表达了这一层），同品质同价时由「增强款 > 队友 > 便宜」决出。
回归用例 `tests/test_training_rules.py::test_plus_suffix_is_not_score`。

### 卡片怎么定位（2026-11-01 修）

卡片**优先靠价格药丸定位**（每张卡底部一个 60/80 的数字）。但价格数字是
**晚于卡面渲染**的：2026-11-01 15:09 实跑里，卡面文字（`训练增强`/`运控增加+++`）
已经画出来了，价格还没画出来 —— 旧代码「没价格 = 没卡」，于是：

- 读不到卡 → 等动画的逻辑以为页面是空的 → 退出 → 白丢一次扭蛋；
- 等动画的旧阈值（连续 2 拍读不到就退出）正好卡在这个**中间态**上。

现在：

1. 没有价格时，改用**卡名行**（`投射增加++` 这种，落在标题带 `GACHA_TITLE_BAND`）
   按列聚类反推列中心 → 卡照样认得出来，`price` 为 `None`；
2. `price is None` 的卡**不作为候选**（买不起点「确定」会卡在扭蛋页反复点），
   而且不算「卡片已稳定」→ `settle_gacha_cards` 会**继续等**；
3. 连续读不到卡的阈值从 2 拍放宽到 4 拍（`GACHA_EMPTY_LIMIT`，约 3.2 秒）。

### 「今天去过步行街」记在哪（2026-11-01 修）

| 状态 | 含义 | 什么时候写 |
|---|---|---|
| `visited` | 今天**进过**步行街 | `handle_street` 认到扭蛋页 |
| `gacha_tried` | 今天**试过**抽扭蛋（买没买成都算） | `handle_street` 认到扭蛋页 |
| `gacha_spent` | 今天**买成了** | 点「确定」成功 |

地图上按 `gacha_tried` 排除步行街（试过了就不再试），按 `gacha_spent` 决定
还要不要去餐厅打工。

**为什么不能只按 `visited` 排除**：15:09 那次没买到，如果完全不登记，
回到地图 todo 里还留着步行街 → 又点进去 → 又失败 → **无限循环**。
所以「进过」和「买成」必须分开记。

另外 `weekend_state()` 现在**不会**因为顶栏 OCR 抖一帧就清空当天状态
（原来 key 一变就整个重建 `_weekend`，`visited`/`gacha_spent` 全丢 →
当天「已经买过扭蛋」的事实没了，又要去餐厅打工一次）。

### 专注怎么读（`/` 被 OCR 读成 `1`）

`57/130` 常被读成 `571130`、`30/130` → `301130`、`17/115` → `971115`
（斜杠那一格被当成数字 1，周数还可能粘在最前面：`3 251130` = 25/130）。
`top_bar` 现在两层兜底（实现见 `TrainingParsersMixin.top_bar`）：

1. **拆粘连串**：末 3 位当上限（100~200），前面的数字枚举所有连续子串当「当前值」候选；
2. **专注条仲裁**：顶栏药丸 = 黄色填充段 + 灰色空段，总宽和左沿是固定版式
   （`0.2885w` / `0.2010w`，1920/1549/1307 三种画面完全一致），填充比例换算专注
   与 OCR 正读值逐帧相等（58/115、40/115、50/115、75/121、61/121、87/117、94/130、57/130），
   用它在候选里挑最近的那个（容差 5）。

只在 OCR 解不出专注、或与像素差 > 2 时才改判；上限没读过就返回 None（不猜）。
同一帧结论缓存一次，避免两次调用给出 56/57 两个值。

### 星期几怎么读（会被 OCR **丢字**，2026-11-02 实测 1136 帧定案）

用户反馈「星期一 星期二 的识别有问题」。查完 1136 张存证帧的结论：

| 结论 | 数据 |
|---|---|
| 整帧 OCR **从来没读错**星期几 | 能读出来的 1023 帧，值 100% 正确 |
| 问题全是**丢字** | 丢字率 9.9%（1136 帧里 113 帧读不出星期几） |
| 丢字率**跟笔画数成反比** | 星期一 67.7% / 星期二 0% / 星期三 0% / 星期四 0% / 星期五 0% / 星期六 7.5%（读成「期大」）/ 星期日 0% |

原因看像素就明白：**「一」只有一条横线**，OCR 的检测框把它并进「期」里，
整词于是变成「星期」两字（框里只剩「星期」/「星期-」）。
「二」有两条横线、「三」三条，笔画够，不会丢。

**所以「二」本身没问题** —— 166 张「星期二」的帧全部读对。
真正读不出的是「一」（67.7%）。裁图人工核对 117 张残框帧，
**全部**是「星期一」，没有一张是「二」。

丢字形态一共 4 种：`星期`(70) / `星期-`(38) / `期日`(12) / `期大`(5=星期六)。

**兜底**（实现见 `src/tasks/ui/topbar_day.py`）：
`top_bar()` 读不出星期几时，把那块裁出来放大 3 倍**重读** ——
检测阶段会重新切分，单独那条横线就成了独立的框，识别成「一」。

- 区域位置：归一化 `x 0.092~0.192, y 0~0.075`（实测框在 `x 0.1014~0.1762`，两侧留余量）
- 放大倍数 **3**：实测 x3 在 1031 帧上与整帧 OCR 100% 一致；x4 起开始丢（x5 有 6/51 读不出，x6 连「星期二」都掉）
- 判据**只认整词**「星期X」（三个字，不多不少）：正文里的「星期日要训练」「比赛后期」都不算
- 读不出就返回 None，**绝不猜** —— 猜错会让 `day_state()` 整个重置

效果（`tools/check_topbar_day.py` 离线回归）：
整帧读得出的 1065 帧，区域重读 **100% 一致**（兜底不改已读对的结论）；
整帧读不出的 117 帧，区域重读救回 **116 帧（99.1%）**。

### 品质色怎么判（2026-11-01）

- **彩色**（训练等级提升后解锁）的卡头是**整条彩虹渐变**，中位色相落在紫区
  （实测帧 `logs/now.jpg` 中间那张 `体能增加+++` H≈121），只按中位色相判就会当成「紫」，
  于是被金卡压掉 → 点错。现在 `card_band_quality` **先认彩虹**：
  色相 30° 一档，**≥3 档各占 ≥10% 且最大档 < 0.70** → 彩。
- 单色卡过不了第二条：同帧两张金卡最大档 0.96~1.00，紫/蓝同理。
- 游戏厅卡面（`card_quality_at(..., rainbow=False)`）不判彩色，免得上高光被误判。

### 恢复精力卡的关键字（2026-10-27 用户截图）

金卡「**精力恢复++**」是当前收益最高的一类，OCR 写法：

```
立刻恢复90精力，之后每天恢复30点，持续4天，队友属性大幅提升
```

- `stamina_recover()` 只认两类片段：`恢复<N>精力` / `恢复<N>点`，以及
  `每天恢复<N>点…持续<D>天`（N×D）。上面这张 = 90 + 30×4 = **210 点**。
- 含「清空 / 消耗」的卡一律按 0 计（相反效果），绝不与恢复卡混淆。
- 评分：`min(恢复量, 精力上限 - 当前精力) × 0.5`。45/130 时恢复卡得 42 分，
  正好压过同为 141 分的「运控增加++」；满精力时 room=0，不会白花钱。
- 识别不到顶栏专注（`stamina=None`）时不分恢复加成，保持旧行为。

## 4. 商店

实现：`handle_shop`（进店由 `handle_go_out` 按日程决定）

- **进店时机**（2026-10-29）：**比赛日、进比赛之前**，训练流 / 商店流各进一次
  （`handle_pre_match_shop`：训练日主界面 + 右下主按钮是「比赛/VS」+ 右上「商店」）。
  周末首页**不再进店**；其他流派比赛日也不进。
- `购买策略 = 只买金和紫`：只买金/紫；金优先，同品质买价格更高的。
- **钱够就买**：没有余额门槛，买不起才关店。
- 0 元商品（白神时久）优先拿：不花零用钱，与品质、余额都无关。
- 比赛前一天进店时把零用钱花光（`赛前清空余额` 打开时）。
- **不限制购买件数**：一拍买一件，买完重新 OCR 再决定（见 5.1）。
- 只有「同一件商品连点 3 次、零用钱没变、卡片还在」才判定没成交并关店（`buy_stalled`）。

## 5. 游戏厅

实现：`handle_arcade`

- 有「跳过 / 已三星」→ 点跳过 + 确定。
- 只买带「自动」的金/紫卡片，按奖励上限从高到低。
- **不限制购买次数**：成交会让零用钱变少，下一拍可以继续买（羽漱川湊能买两次）。
- 零用钱读不到 → 不买（盲买就是 2026-10-29 的死循环）；0 元卡片例外。
- 同一张卡连点 3 次没成交（零用钱没变、卡片还在）→ 退出游戏厅。
- 没有可跳过的小游戏、也没买成 → 点右上角返回，当天不再进。

## 5.1 角色特例：按界面事实判断，不按角色名写死

| 能力（举例） | 界面上看到什么 | 代码怎么判 |
|---|---|---|
| 羽漱川湊：能买两次 | 同类商品可以连续成交 | 不设次数上限；成交会让零用钱变少，`buy_stalled` 的 key 自然变，计数归零 |

## 6. 训练科目

实现：`handle_subject_select` / `scoring.py`

- 评分 = 队友数×1.0 + 器材数×1.0 + 经理×**2.1** + 金框×**1.2** + 彩框×**2.3**。
  （2026-10-29 用户口径：彩框抬到 2.3，压过经理 —— 有彩框就该练。
  金框/彩框指**训练科目按钮外面那一圈**（装备、经理经验满了会点亮），不是器材卡上的框——
  按器材卡的金框再算一次会和「器材数」重复计分（用户 2026-10-27 口径）。
- **彩框判据**（2026-10-31 两次重标定，`parsers.has_crit_border`）：只采以该行文字为中心的
  **上下两条边**、x 0.74~0.98w、半窗 **±0.050h**，品红/绿像素占比 ≥ **0.13**
  且高于其它行最低值的 **2 倍**。实测：真彩框 **0.157~0.39**（同一科目会闪，单帧只是下界）、
  噪声 **0.000~0.109**。旧口径（半窗 ±0.06h + 门限 0.20）会让选中行噪声（0.21）冒充彩框；
  门限定 0.22 又会把 0.157 的弱彩边漏掉（用户 2026-10-31 两次当场发现）。
- `满经验`（器材卡 MAX）在日志里会给出来，但**不进评分**（框已经代表「满经验点亮」，
  再算一次会重复计分）。
- 先只看**有队友**的科目，按屏幕从上往下逐个探测。
- 排序：分数 → 队长推荐属性 → 当前数值低的（成长空间大）→ 屏幕上靠前（兜底）。
- 失败率 > `失败率上限(%)`（默认 50）→ 退出科目页并强制休息（`_force_rest`）。
- 训练日精力 < 阈值 → 休息（`flow.rest_threshold`）：
  - 平时：`休息精力阈值`（默认 40）；
  - **周二**（2026-11-02 用户口径）：硬阈值 **60**，取 `max(配置值, 60)`，跟流派无关；
  - **周四不再有特殊阈值**（旧的 75 已取消），回到 `休息精力阈值`。

## 11. 快速比赛（常驻模块）

实现：`src/tasks/QuickMatchTask.py`（TriggerTask，默认关闭）

- 管的是**养成之外**的比赛：全国大赛 / 圣山战 / 竞技场（用户手动进的那些局）。
  **养成流程里的比赛不归它** —— 那由 `TrainingTask` 自己的比赛逻辑处理
  （用户 2026-11-02 口径：「自动训练跟快速比赛是无关的两个模块」）。
- 任何模式（赛事 / 大厅 VS / 剧情比赛）走同一套：赛前准备 → 开场 ▶▶ → 跳球 → 比赛 → 结算。
- 只在**没有 onetime 任务在跑**时被调度（`TaskExecutor.next_task` 里 onetime 优先），
  所以养成任务运行时它自动让位，不会抢点击。
- 默认关闭；在任务页或监控页的「快速比赛」开关启用后才接管。
- 监控页的开关只管**这个模块自己**（`MonitorTab.set_quick_match`）：
  - 开 = enable `QuickMatchTask` + **顺手**唤醒执行器（`executor.start()`；
    接入 / 拉游戏仍归监控页第一栏【启动】）；
  - 关 = 只 disable 自己，**绝不去 pause 执行器**（跟第二栏【暂停】一样）；
  - 执行器被第一栏【停止】关掉时，本开关跟着复位成「关」（运行基础没了）。
- 比赛内「选择技能 / 事件二选一」有开关 `比赛内自动选技能和事件`（默认开）。
  用户口径：点过「自动」之后这些通常不用点；实跑确认后再决定是否默认关。
